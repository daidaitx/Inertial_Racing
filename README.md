# Inertial Racing – 惯性赛车强化学习环境与算法对比

本项目为《强化学习基础》课程期末项目，实现了一个具有惯性动力学的网格世界赛车环境，并对比了有模型方法（价值迭代）与无模型方法（Q‑learning）在该环境下的表现，同时验证了死亡动作过滤对 Q‑learning 样本效率的提升效果。

## 项目结构

```
.
├── main.py                   # 主入口：运行单个赛道或批量实验（含价值迭代+Q‑learning）
├── run_convergence_ql.py     # 公平早停实验：Q‑learning 达到最优代价即停止（排除检测开销）
├── ablation_death_filter.py  # 消融实验：对比探索时是否过滤已知死亡动作
├── plot_results.py           # 绘制论文所需所有图表（输出到 summary_figs/）
├── postprocess_results.py    # 统计汇总实验结果，生成 results_summary.csv
├── requirements.txt          # 依赖列表
├── README.md                 # 本文件
├── tracks/                   # 赛道文本文件及静态数据 track_data.csv
├── src/                      # 核心模块（环境、算法、可视化等）
├── logs/                     # 实验日志与结果 CSV（自动生成）
├── outputs/                  # 生成的赛道布局、轨迹、热力图等图片
└── summary_figs/             # 论文用汇总图表（由 plot_results.py 生成）
```

## 环境描述

- 赛车具有惯性：状态定义为 `(当前位置, 上一位置)`，速度隐含在两者差中。
- 动作空间：9 个方向 `(dx, dy) ∈ {-1,0,1}^2`。
- 每步惩罚 `-10`；到达终点额外获得深入奖励（0~10，基于终点离可行驶区域的 BFS 距离）。
- 撞墙或驶出赛道立即死亡（奖励 `-inf`）。
- 状态空间通过 BFS 从所有起点出发构建，仅保留可达的 `(cur, prev)` 对，大幅压缩状态数（例如 custom 赛道压缩率达 99.36%）。

## 算法实现

### 价值迭代（有模型）
- 利用环境预计算的转移表 `transitions`，异步 Gauss‑Seidel 就地更新。
- 收敛阈值 `θ = 1e-6`，折扣因子 `γ = 1`。

### Q‑learning（无模型）
- ε‑greedy 策略，初始 `ε = 1.0`，指数衰减至 `ε_min = 0.1`。
- 学习率 `α = 1.0`。
- **改进点**：探索时只从已知非死亡动作（`Q > -inf`）中随机选择，避免无效死亡幕，提高样本效率。

### 消融实验
- 赛道：`U_shape_with_narrow_shortcut`，目标最优代价 `100`。
- 对比两种模式：`filter`（过滤死亡动作）vs `no_filter`（允许任何动作，死亡奖励改为 `-500` 以保证数值稳定）。
- 每组重复 50 次（最终数据），早停条件为当前最优代价 ≤ 100，且检测间隔为 1 幕（检测不计时）。

## 如何运行

### 1. 安装依赖
```bash
pip install -r requirements.txt
```

### 2. 运行完整实验（价值迭代 + Q‑learning 固定幕数）
修改 `main.py` 中的 `track_name` 和 `run_vi` / `run_ql` 标志，或直接运行默认配置（会顺序执行所有赛道）：
```bash
python main.py
```
结果自动写入 `logs/run_all.csv`，并生成 `results_summary.csv`。

### 3. 运行公平早停实验（Q‑learning 自动收敛）
```bash
python run_convergence_ql.py
```
结果保存在 `logs/convergence_ql.csv` 和 `logs/convergence_ql_summary.csv`。

### 4. 运行消融实验
```bash
python ablation_death_filter.py
```
结果保存在 `logs/ablation_death_filter.csv`。

### 5. 生成论文图表
确保所有 CSV 文件已存在，然后运行：
```bash
python plot_results.py
```
图表输出至 `summary_figs/` 文件夹。

### 6. 统计汇总已有结果
```bash
python postprocess_results.py
```
生成 `results_summary.csv` 并在控制台打印对比表格。

- Q‑learning 在给定足够幕数下总能达到与价值迭代相同的最优代价（所有赛道 `best_cost` 与价值迭代完全一致）。

## 消融实验：死亡动作过滤

在 `U_shape_with_narrow_shortcut` 赛道上（目标代价 100），对比两种探索策略：

| 模式 | 收敛幕数（均值±标准差） | 训练时间（ms，均值±标准差） | 最终代价 |
|------|------------------------|------------------------------|----------|
| **filter**（过滤死亡动作） | $8801 \pm 126$ | $1074 \pm 86$ | 100.0 |
| **no\_filter**（允许死亡动作） | $10357 \pm 178$ | $946 \pm 140$ | 100.0 |

- **样本效率**：`filter` 模式平均幕数减少 **约 15%**，说明过滤死亡动作能有效避免无效探索，加速收敛。
- **训练时间**：`filter` 模式的时间反而略高于 `no_filter` 模式。原因在于：
  - `no_filter` 模式中大量幕在第一步或前几步就撞墙死亡（每步 `-inf` 奖励，立即终止），这些短幕的平均步数远小于 `filter` 模式中的长幕（后者能安全探索到终点附近）。因此，尽管 `no_filter` 需要更多幕，但其总交互步数（幕数 × 平均步数）可能并不更高。
  - `filter` 模式每步需要执行 `np.where(q_vals > -np.inf)` 来排除死亡动作，引入了额外的计算开销。
- **最终策略**：两种模式均能收敛到最优代价 100，证明过滤操作不影响最终性能。

**结论**：死亡动作过滤有效提升了样本效率（幕数减少约 15%），但在本实验环境中并未转化为训练时间的节省，反而因为每幕步数更长和动作选择开销，时间略有增加。这一现象揭示了样本效率与计算效率之间的权衡。
